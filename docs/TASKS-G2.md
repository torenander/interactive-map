# G2 — Schema and client

**Goal:** Migrations 0001–0004 from `docs/DATA-MODEL.md` applied, types generated, typed
Supabase client with email auth. Full spec: `docs/OBJECTIVES.md` § G2, `docs/DATA-MODEL.md`.

**Environment note:** Docker Desktop is required for `supabase db reset` and
`supabase gen types`. It was not running when this breakdown was written. Tasks that
need it are flagged; they are authored regardless and verified as soon as Docker comes up.

## File structure

| File | Responsibility |
|---|---|
| `supabase/config.toml` | Local Supabase stack config (`supabase init`). |
| `supabase/migrations/0001_tables.sql` | `areas`, `area_cells` tables + indexes. |
| `supabase/migrations/0002_derive_cells.sql` | H3 cell derivation trigger. |
| `supabase/migrations/0003_touch_updated_at.sql` | `updated_at` maintenance trigger. |
| `supabase/migrations/0004_rls.sql` | Row-level security policies. |
| `src/db/types.ts` | Generated by `supabase gen types typescript --local`. Never hand-edited once generated. |
| `src/db/client.ts` | Typed `SupabaseClient<Database>` singleton + email-auth helpers (`signUpWithEmail`, `signInWithEmail`, `signOut`). |
| `.env.example` | Documents `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. |
| `tests/unit/schema.test.ts` | The five G2 exit assertions, against the local Supabase instance. |

      `ERROR: extension "h3" is not available (SQLSTATE 0A000). Could not open extension
      control file ".../extension/h3.control": No such file or directory.`
      Verified this is not a naming or signature issue: listed every `*.control` file bundled
      in `public.ecr.aws/supabase/postgres:17.6.1.167` (the image `major_version = 17` in

      the signature-drift hazard `docs/DATA-MODEL.md` flagged; the extension is not packaged
      in the local dev Postgres image at all, on any Postgres major version this CLI ships.
      Did not touch migration 0002's function call — there is nothing to fix there until the
      extension itself exists locally. Did not build a custom Postgres image to add it — that
      is a real infra decision (which h3-pg build, pinned where, who maintains it) outside
      "fix the call in 0002" and outside `supabase/**` as scoped to me. Stopping and reporting
      per `docs/OBJECTIVES.md`: "If a check is wrong, stop and say so."
