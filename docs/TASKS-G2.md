# G2 — Schema and client

**Goal:** Migrations 0001–0004 from `docs/DATA-MODEL.md` applied, types generated, typed
Supabase client with email auth. Full spec: `docs/OBJECTIVES.md` § G2, `docs/DATA-MODEL.md`.

**Architecture deviation (2026-09-10):** `h3` / `h3_postgis` are not available as Postgres
extensions in any Supabase Postgres image, local or hosted — verified directly against
`supabase/postgres:17.6.1.167` and `:15.14.1.170`, and against upstream (`supabase/postgres`
issues #245 and #664, org discussion #9687, open since 2022). Team lead's decision: cell
derivation moves from a Postgres trigger to a Supabase Edge Function (`save-area`) using
`h3-js`, per the "or edge function" alternative `docs/ARCHITECTURE.md` already named. See
Task 3 and Task 10 for the full history and the fix.

## File structure

| File | Responsibility |
|---|---|
| `supabase/config.toml` | Local Supabase stack config (`supabase init`). |
| `supabase/migrations/0001_tables.sql` | `areas`, `area_cells` tables + indexes. `h3_index` is `text`, not `h3index`; postgis only, no h3/h3_postgis extensions. |
| `supabase/migrations/0002_derive_cells.sql` | Superseded, intentional no-op — see Task 10. |
| `supabase/migrations/0003_touch_updated_at.sql` | `updated_at` maintenance trigger. |
| `supabase/migrations/0004_rls.sql` | Row-level security policies. |
| `supabase/functions/save-area/index.ts` | Sole write path for `areas`. Computes H3 cells via `h3-js`, upserts the area, replaces its cell set wholesale. Runs with the caller's JWT. |
| `src/db/types.ts` | Generated by `supabase gen types typescript --local`. Never hand-edited. |
| `src/db/client.ts` | Typed `SupabaseClient<Database>` singleton, email-auth helpers (`signUpWithEmail`, `signInWithEmail`, `signOut`), and `saveArea()` wrapping the edge function. |
| `.env.example` | Documents `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. |
| `tests/unit/schema.test.ts` | The five G2 exit assertions, against the local Supabase instance. |

## [x] Task 3 — Migration 0002: cell derivation — history of the blocker

- [x] **Step 1:** `supabase/migrations/0002_derive_cells.sql`, originally verbatim from
      `docs/DATA-MODEL.md` § Migration 0002 (a trigger calling `h3_polygon_to_cells`).
- **What happened:** `npx supabase db reset` failed applying **0001**, not 0002:
  `ERROR: extension "h3" is not available (SQLSTATE 0A000). Could not open extension
  control file ".../extension/h3.control": No such file or directory.`
  Verified this is not a naming or signature issue: listed every `*.control` file bundled
  in `public.ecr.aws/supabase/postgres:17.6.1.167` (the image `major_version = 17` in
  `supabase/config.toml` resolves to) — 85 extensions present, including `postgis` at
  3.3.7, but **no `h3` or `h3_postgis` control file anywhere in the image**. Re-confirmed
  after a Docker restart, at team lead's request: identical failure, deterministic, not a
  transient Docker hiccup. Team lead independently checked the pg15 image
  (`supabase/postgres:15.14.1.170`) — same result — and confirmed h3-pg is not available
  on hosted Supabase either (open feature requests `supabase/postgres#245`, `#664`, org
  discussion `#9687`, unresolved since 2022).
- **Resolution (Task 10):** a custom local Postgres image would only have masked the
  problem — hosted Supabase still couldn't run the trigger, and this project may be
  commercialised on hosted Supabase (`SPEC.md`). Team lead's decision: derive cells in a
  Supabase Edge Function (`save-area`) using `h3-js` instead of a Postgres trigger. This
  migration is now an intentional no-op documenting why; see Task 10.
- [x] **Step 3:** Commit — `feat: derive area_cells from geometry via trigger`, superseded
      by `fix: drop unavailable h3/h3_postgis extensions, neuter derive-cells trigger`.

## [x] Task 10 — Architecture pivot: h3-js edge function, not Postgres trigger

Team lead's decision after confirming h3-pg is unavailable on both local and hosted
Supabase (see Task 3). Full rationale in `docs/ARCHITECTURE.md` § "Cell derivation runs
server side" (superseded note, single section — the only part of that file this task
touched).

- [x] **Step 1:** `supabase/migrations/0001_tables.sql` — dropped `create extension h3` /
      `h3_postgis`; `area_cells.h3_index` changed from `h3index` to `text`. Commented
      inline with the reason and a pointer to this task.
- [x] **Step 2:** `supabase/migrations/0002_derive_cells.sql` — rewritten to an
      all-comment, intentional no-op (removes the trigger and the
      `h3_polygon_to_cells` call). Kept as a file so the 0001–0004 sequence still lines up
      with `docs/DATA-MODEL.md`.
- [x] **Step 3:** `docs/ARCHITECTURE.md` — appended a superseded note to the one section
      I own, without deleting the original text, per that file's own header rule.
- [x] **Step 4:** `supabase/functions/save-area/index.ts` — new edge function. Runs with
      the caller's JWT (not service role) so RLS still applies. Validates the request,
      computes cells with `h3-js` `polygonToCells(coordinates, 10, true)`, upserts the
      `areas` row (`onConflict: id`, so a client-generated uuid retried twice is
      idempotent per `docs/DATA-MODEL.md`'s offline-queue contract), then deletes and
      re-inserts `area_cells` for that `area_id` — replace, never append. Deletes of whole
      areas are not routed through this function; the FK `on delete cascade` in migration
      0001 handles cell cleanup on a direct client delete.
- [x] **Step 5:** `src/db/client.ts` — added `saveArea()` typed wrapper around
      `supabase.functions.invoke('save-area', ...)`.
